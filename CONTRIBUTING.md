# Contributing

Open an issue for a proposed change to the workflow's behavior. Include the scenario, the current outcome, and the outcome you expect. Small fixes to wording, examples, and broken links can go directly to a pull request.

Fork the repository if you need write access, create a branch, and open a pull request against `main`. Describe the behavior or documentation you changed and include the checks you ran.

## Before opening a pull request

- Check that `AGENTS.md`, `WORKFLOW.md`, and the templates agree on approval gates, dependencies, and evidence.
- Check relative links from a clean checkout and run `git diff --check`.
- For setup changes, follow the README from a fresh checkout at a different path. Record the runtime and which scope cases you verified.
- Use placeholders and fictional examples for paths, account names, and initiative records. Review the diff and Git author information for anything you intend to keep private.
